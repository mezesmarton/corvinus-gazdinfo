> [!abstract] Rövid összefoglaló
> Ez a jegyzet a hálózati szolgáltatások és a vállalati Windows Server alapjaiba nyújt betekintést. Részletesen tárgyalja a kliens-szerver architektúrát, a legfontosabb hálózati protokollokat (DNS, DHCP, SMB, HTTP/HTTPS), az Active Directory (AD DS) hierarchiáját, valamint a fájl- és mappakezelés automatizálását a Windows PowerShell segítségével.

## 1. Kliens-Szerver Architektúra és a Szolgáltatások Alapjai

Egy hálózati szolgáltatás sikeres működéséhez három alappillér együttes megléte szükséges: a **hálózat** (ami biztosítja az eszközök közötti IP és routing kommunikációt), az elérhető **szerver**, és a rajta futó **szolgáltatás** (amely egy meghatározott porton figyel).

> [!definition] Kliens-Szerver modell
> Olyan hálózati kommunikációs forma, amelyben a feladatok megoszlanak a szolgáltatást igénylő **kliensek** és a szolgáltatást nyújtó **szerverek** között. A kapcsolatot mindig a kliens kezdeményezi (Kérés / Request), a szerver pedig a háttérben figyel, feldolgozza a kérést és visszaküldi az eredményt (Válasz / Response).

> [!danger] Fontos: Mi a szerver valójában?
> A "szerver" a hálózatban elsősorban egy **szerep**, nem pedig egy speciális fizikai hardver. Akár egy egyszerű laptop vagy egy virtuális gép (Azure VM) is működhet webszerverként, ha a megfelelő szolgáltatás fut rajta.

## 2. A Windows Server Alapjai

A Windows Server a Microsoft vállalati operációs rendszere, amely hálózati és vállalati szolgáltatások nyújtására specializálódott. Két fő kiadása van:
*   **Standard:** Kisebb virtualizációs igényekhez, korlátozott VM-jogosultságokkal (pl. fájlszerver, DNS, DHCP).
*   **Datacenter:** Erősen virtualizált adatközponti környezetekhez, korlátlan VM-jogosultságokkal.

### 2.1 Szerepkör (Role) vs. Funkció (Feature)
A szerver szolgáltatásait a *Server Manager* vagy a *Windows Admin Center (WAC)* grafikus felületein keresztül kezelhetjük.

| Fogalom | Leírás | Példa |
| :--- | :--- | :--- |
| **Szerepkör (Role)** | Meghatározza a szerver *fő feladatát* és célját a hálózatban. | Web Server (IIS), DNS Server, DHCP Server, Active Directory. |
| **Funkció (Feature)** | Kiegészítő, *támogató képességet* ad az operációs rendszerhez. | .NET Framework, BitLocker, Windows Server Backup. |

## 3. Alapvető Hálózati Szolgáltatások

### 3.1 DNS (Domain Name System)
A DNS egy fordított fa-struktúrájú hierarchikus névtér, amely az ember számára olvasható neveket (pl. `www.example.com`) IP-címekké alakítja (és fordítva).

> [!done] 💡 Érthető magyarázat
> A DNS a számítógépes hálózatok "telefonkönyve". Amikor beírod a böngészőbe egy weboldal nevét, a géped megkérdezi a DNS-szervert (fellapozza a telefonkönyvet), amely visszaadja a weboldalhoz tartozó pontos IP-címet (telefonszámot).

**Fontosabb DNS Rekordtípusok:**
*   **A:** Név -> IPv4-cím.
*   **AAAA:** Név -> IPv6-cím.
*   **CNAME:** Álnév egy másik DNS-névre.
*   **MX:** Levelezőszerver megadása.
*   **PTR:** Fordított feloldás (IP-cím -> Név).

*PowerShell lekérdezés:* `Resolve-DnsName google.com -Type A`.

### 3.2 DHCP (Dynamic Host Configuration Protocol)
A DHCP automatikusan kiosztja a hálózati beállításokat (IP-cím, maszk, alapértelmezett átjáró, DNS) a klienseknek egy meghatározott bérleti időre (lease).

> [!example] A DORA folyamat
> A címkiosztás a **DORA** folyamaton keresztül zajlik (UDP 67 és 68-as portokon):
> 1. **D**iscover: A kliens IP-címet keres a hálózaton.
> 2. **O**ffer: A DHCP szerver felajánl egy szabad címet.
> 3. **R**equest: A kliens hivatalosan kérelmezi az ajánlott címet.
> 4. **A**cknowledge: A szerver jóváhagyja és rögzíti a bérletet.

### 3.3 Fájlmegosztás (SMB és NTFS)
A vállalati fájlmegosztás az **SMB (Server Message Block)** protokollon (TCP 445) keresztül történik. A megosztott mappák UNC-útvonallal érhetők el (pl. `\\SERVER01\Documents`).

A hozzáférést két jogosultsági réteg szabályozza:
1.  **Megosztási jogosultság (Share):** A hálózaton keresztüli elérést szabályozza (Read, Change, Full Control).
2.  **NTFS-jogosultság:** A helyi fájlrendszeren érvényesülő jogok (Read, Modify, Full Control).

> [!danger] A szigorúbb nyer!
> Hálózati elérésnél a Share és az NTFS jogosultságok *együtt* érvényesülnek. Ha eltérés van közöttük, mindig a **szigorúbb** korlátozás lép érvénybe (pl. ha a Share Full Control, de az NTFS csak Read, a felhasználó csak olvasni tud).

### 3.4 Webszerver (IIS) és FTP
A Windows Server webalapú szolgáltatásaiért az **IIS (Internet Information Services)** felel.
*   **HTTP:** Titkosítatlan kommunikáció (TCP 80).
*   **HTTPS:** TLS tanúsítvánnyal titkosított kommunikáció (TCP 443).
*   **Binding (Kötés):** Határozza meg, hogy egy adott webhely melyik **IP-címen + Porton + Host name-en** fogadja a beérkező kéréseket.
*   **FTP (File Transfer Protocol):** Kifejezetten fájlok fel- és letöltésére szolgáló szolgáltatás (szintén az IIS része).

## 4. Active Directory (AD DS) és Központi Kezelés

Egy bizonyos méret felett a gépek és felhasználók egyenkénti kezelése lehetetlen. Erre jelent megoldást a Tartományvezérlő (Domain Controller) és az **Active Directory Domain Services (AD DS)**.

**Az AD Hierarchikus Struktúrája:**
1.  **Erdő (Forest):** A legfelső szintű logikai tároló.
2.  **Fa (Tree):** Tartományok összefüggő struktúrája.
3.  **Tartomány (Domain):** Közös címtáradatbázist használó erőforrások gyűjteménye.
4.  **Szervezeti Egység (Organizational Unit - OU):** AD objektumok tárolói, amelyekre csoportházirendeket (GPO) alkalmazhatunk.

> [!tip] Csoportházirend (Group Policy Object - GPO)
> A GPO-k segítségével konfigurációs és biztonsági beállításokat kényszeríthetünk központilag a hálózat gépeire és felhasználóira (pl. jelszóházirendek, mappamegosztások).

## 5. PowerShell: Fájl- és Mappakezelés

Az üzemeltetés és automatizálás alapja a parancssoros környezet. A klasszikus (CMD) parancsok PowerShell (Cmdlet) megfelelői:

| Funkció | PowerShell Cmdlet | Régi CMD Parancs |
| :--- | :--- | :--- |
| Mappa tartalmának listázása | `Get-ChildItem` | `DIR` |
| Be- és kilépés mappából | `Set-Location` | `CD` |
| Új fájl vagy mappa létrehozása | `New-Item` | `MD` / `COPY CON` |
| Fájl vagy mappa törlése | `Remove-Item` | `DEL` / `RD` |
| Fájl vagy mappa másolása | `Copy-Item` | `COPY` |
| Fájl vagy mappa átnevezése | `Rename-Item` | `REN` |
| Fájl tartalmának megtekintése | `Get-Content` | `TYPE` |

> [!cite] Attribútumok módosítása (Get-Item)
> Fájlok attribútumainak (pl. Rejtett, Írásvédett) módosítása két lépésben történik:
> 1. Elmentjük a tulajdonságokat: `$a = Get-Item -Path fajlnev`
> 2. Beállítjuk az újakat: `$a.Attributes = "ReadOnly, Hidden"`

> [!example] Számított tulajdonságok (Calculated Properties)
> Ha a lekérdezés kimenetében (a `Select-Object` segítségével) egy olyan egyedi oszlopot szeretnénk létrehozni, amit egy matematikai képlet számol ki (pl. fájlméret MB-ban), egy speciális hash-táblát kell írnunk:
> `@{Name='SizeMB'; Expression={[math]::Round($_.Length / 1MB, 2)}}`

## Vizsgakérdések az ismétléshez

> [!faq]- Mi a különbség a Windows Server szerepkör (Role) és funkció (Feature) között?
> A **Szerepkör (Role)** határozza meg a szerver fő feladatát és hálózati célját (pl. DNS Server, DHCP Server, Web Server (IIS)). A **Funkció (Feature)** ezzel szemben olyan kiegészítő, támogató képességet ad az operációs rendszerhez, amely önmagában nem egy komplett hálózati szolgáltatás (pl. .NET Framework, BitLocker, Windows Server Backup).

> [!faq]- Egy felhasználó hálózaton keresztül egy SMB megosztáshoz csatlakozik. A Share (megosztási) jogosultsága "Full Control", de az NTFS jogosultsága csak "Read". Milyen műveleteket végezhet a mappában?
> A felhasználó kizárólag olvasni tudja a fájlokat. Hálózati elérés esetén a Share és az NTFS jogosultságok együttesen érvényesülnek, és mindig a **szigorúbb** korlátozás (jelen esetben az NTFS szerinti "Read" jogosultság) lép életbe.

> [!faq]- Milyen lépéseken (protokollfolyamaton) keresztül kap IP-címet egy kliens a hálózatban a DHCP szervertől?
> A DHCP a **DORA** folyamatot (UDP 67-68 portokon) használja a címkiosztásra: 1. **D**iscover: a kliens megkeresi a DHCP szervert a hálózaton. 2. **O**ffer: a szerver felajánl egy szabad IP-címet. 3. **R**equest: a kliens hivatalosan kéri az ajánlott címet. 4. **A**cknowledge: a szerver jóváhagyja a bérletet (lease).

> [!faq]- Sorold fel az Active Directory (AD DS) négy fő hierarchikus logikai elemét (szintjét)!
> A hierarchia legfelső szintje az **Erdő (Forest)**, ezen belül helyezkednek el a **Fák (Tree)**. A fák **Tartományokból (Domain)** épülnek fel, amelyek a közös címtár-adatbázist használó objektumok gyűjteményei. A tartományokon belül pedig **Szervezeti Egységeket (OU)** hozhatunk létre az objektumok rendszerezésére és csoportházirendek (GPO) alkalmazására.

> [!faq]- Melyik PowerShell parancs felel meg a klasszikus parancssoros "DIR" utasításnak, és hogyan lehet vele egy egyedi, számított oszlopot (pl. méret MB-ban) is megjeleníteni?
> A mappa tartalmának listázására a `Get-ChildItem` parancs szolgál. Számított oszlop (Calculated Property) megjelenítéséhez a lekérdezést a `Select-Object` parancsnak kell átadni a pipeline (`|`) segítségével, ahol a következő szintaxist kell használni: `@{Name='OszlopNeve'; Expression={kifejezés}}`, például: `@{Name='SizeMB'; Expression={[math]::Round($_.Length / 1MB, 2)}}`.
